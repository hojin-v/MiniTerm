# 테스터 안내

첫 배포는 `v0.1.0-alpha.1`, Windows 11 x64용 제한된 알파다. 기본 Git Bash의 리사이즈 입력 누락과 일부 메모리 목표 초과가 남아 있다. 안정판 터미널을 대체하는 용도로 권장하지 않는다.

## 설치

1. Git for Windows와 DX12 지원 그래픽 드라이버를 준비한다.
2. [Releases](https://github.com/hojin-v/MiniTerm/releases)에서 `MiniTerm-0.1.0-alpha.1-windows-x64-setup.exe`와 `SHA256SUMS`를 받는다. `Source code` ZIP은 실행 파일이 아니다.
3. PowerShell의 `Get-FileHash .\MiniTerm-0.1.0-alpha.1-windows-x64-setup.exe -Algorithm SHA256` 결과를 `SHA256SUMS`의 같은 파일 항목과 비교한다.
4. 설치본을 실행한다. 사용자별 `%LOCALAPPDATA%\Programs\MiniTerm`에 설치하며 관리자 권한은 요구하지 않는다. 설치 후 해당 폴더의 `miniterm.exe`를 실행한다.

현재 설치본은 코드 서명이 없다. 출처·해시를 확인하고 조직의 실행 정책을 따른다. 백신을 끄거나 차단을 일괄 우회하지 않는다. Codex·Claude Code·AI Battery는 포함하지 않으며 각 도구의 설치와 로그인을 별도로 준비한다.

압축형 `MiniTerm-0.1.0-alpha.1-windows-x64.zip`은 같은 폴더에 모두 풀고 `miniterm.exe`를 실행한다. 알림 등록은 자동 수행하지 않으며 설정에서 별도로 등록한다. ZIP과 설치본은 같은 설정 경로와 단일 앱 인스턴스를 사용한다. 설정까지 분리된 포터블 모드는 아니다.

## 시험 순서

| 순서 | 확인할 항목 |
| --- | --- |
| 1 | `printf 'Hello, MiniTerm!\n'`, `printf '한글 ABC 123\n'`의 입력·출력 |
| 2 | 제목·본문 위/가운데/아래 더블 클릭으로 확장·축소, 요약의 단일 클릭 시 크기 유지 |
| 3 | 헤더 드래그 이동, 가장자리 크기 조절, 재실행 후 위치와 설정 |
| 4 | 설정을 열어 둔 상태의 다크/라이트 전환, 글꼴·한글·ANSI 강조·투명도 |
| 5 | `sleep 3; printf 'done\n'` 실행 중 숨기기와 복귀, 여러 세션 전환 |
| 6 | 실제 한글 IME 조합·취소·후보창, 선택·복사·붙여넣기와 단축키 |
| 7 | 새 세션에서 이미 설치한 에이전트 실행, 재개 선택창·AI Battery·알림 전달과 클릭 |
| 8 | 명시적인 작업 계획의 현재 태스크·완료 비율, 긴 작업명에 툴팁 하나 |

리사이즈 입력 문제의 재현에는 `printf 'resize-test\n'` 같은 무해한 명령을 사용한다. 첫 글자가 누락되는 경우를 기존의 알려진 문제로 기록한다. 데이터 변경이나 배포 명령으로 시험하지 않는다. 격리된 MSYS 수정 DLL을 사용자 Git 설치 경로에 복사하지 않는다.

계획을 출력하거나 직접 보고하지 않는 에이전트에는 진행률이 표시되지 않을 수 있다. 저장소의 `miniterm-progress` skill은 프로젝트 안의 새 에이전트 세션에서 별도로 시험한다. 요약은 작업 성공이나 소요 시간을 추정하지 않는다.

## 업데이트·되돌리기·제거

진행 중인 작업을 마치고 트레이의 `종료…`로 MiniTerm을 닫은 뒤 새 설치본을 실행한다. 실행 중이면 설치·제거를 중단하며 앱을 강제로 종료하지 않는다. 자동 업데이트 기능은 없고 Releases의 설치 파일로 수동 갱신한다.

설정은 `%LOCALAPPDATA%\MiniTerm\settings.json`이다. 업데이트 전 앱을 닫고 설정 파일을 별도 폴더에 복사하면 되돌리기에 사용할 수 있다. 이전 설치본도 보관한다. 되돌릴 때 앱을 닫고 이전 설치본을 실행하며 현재 버전의 설정 호환성을 확인한다. 깨끗한 환경의 업그레이드·다운그레이드 전체 시험은 아직 완료하지 않았다.

Windows의 설치된 앱에서 MiniTerm을 제거한다. 제거 시 저장된 사용자 설정은 유지한다. 변경된 에이전트 연동 설정을 무조건 삭제하지 않으며 복구에 주의가 필요한 경우 안내한다. 열린 Bash·CLI 작업이 재설치 후 자동 복원되지는 않는다.
