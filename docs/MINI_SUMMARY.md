# 미니 작업 요약

상단에는 **새 탭 · 입력/요약 전환 · 숨기기**만 제공한다. 확장/축소는 더블 클릭, 설정은 Windows 트레이 메뉴에서 사용한다. 확장·알림·설정 버튼을 제거해 제목 공간을 넓혔다.

요약은 현재 태스크와 계획 진행률을 우선한다.

| 위치 | 정보 | 근거 |
| --- | --- | --- |
| 상단 표시줄 | 프로그램 제목 또는 보고된 작업명 | OSC title을 우선한다. 제목이 없으면 보고된 작업명을 사용한다. Codex DB에서 세션명을 추측하지 않는다. 긴 제목은 호버로 확인한다. |
| 본문 첫 줄 | 완료 항목 비율과 실행 상태 | `33% · 1/3 완료 · 작업 중`처럼 비율과 읽기 쉬운 상태를 표시한다. 직접 보고가 없으면 화면에 명시된 계획을 사용한다. |
| 본문 다음 줄 | 진행 중인 태스크, 또는 다음 대기 항목 | 직접 보고된 항목을 우선한다. 중단/오류 시 멈춘 작업을 표시한다. |
| 남는 본문 줄 | 중단 항목, 최근 완료 항목 | 계획의 해당 표시. 창이 작으면 우선순위에 따라 줄 수를 줄인다. |
| 하단 | 실제 AI Battery 줄 | 커서 아래도 탐색하며 원래 ANSI 색·볼드·막대를 유지한다. 배터리가 없으면 Codex 사용량 안내를 대신 넣지 않는다. |

계획이 없으면 현재 화면의 실행 상태와 최근 도구 활동만 사용한다. `Ran`의 명령문·변수·경로·인수는 요약과 호버에 복사하지 않는다. 알아볼 수 있는 명령은 `최근 활동: 파일 내용 확인`, `코드·텍스트 검색`, `프로그램 빌드`, `코드 검증` 등으로 표시하며 용도를 알 수 없는 스크립트는 `최근 활동: 명령 실행`으로 표시한다. `Explored`는 파일·코드 확인, `Edited`는 파일 수정으로 표시한다. 활동명은 작업 목적이나 성공 판정이 아니다. 임의의 최근 출력 줄을 현재 태스크로 선택하지 않는다. 활동도 없으면 `작업 계획 없음`으로 표시한다. 모델을 호출해 요약하거나 전체 작업을 추론하는 기능은 아니다. Bash 종류와 `5h limit`, `/status`, context 안내, shortcuts는 본문에 넣지 않는다.

`Working (58s)`는 `작업 중 · 58초`, `Thinking (1m 24s)`는 `검토 중 · 1분 24초`로 표시한다. 이 시간은 CLI가 제공한 경과 시간이며 남은 작업 시간 예측이 아니다. 긴 제목과 요약 행은 자동 생략 툴팁을 끄고 명시적 안내 하나만 표시한다. 작업명 호버에는 전체 작업명과 계획·보고 출처를 제공하며 작은 창에서는 안내 안에서 스크롤할 수 있다.

진행률은 **완료 항목 수 ÷ 보고된 전체 항목 수 × 100**의 정수값이다. 소요 시간이나 남은 시간, 테스트 성공률을 뜻하지 않는다. 3개 중 1개 완료면 33%이며 계획이 늘면 비율이 낮아질 수 있다. 중단이나 응답 종료만으로 100%가 되지 않는다. `completed` 보고는 미완료 항목이 남아 있으면 거부한다. 화면 분석으로 얻은 계획은 일부 항목이 접히거나 끝이 잘리면 비율을 표시하지 않는다. 화면의 새 Codex 요청 이후에는 이전 계획·활동·최근 실행을 붙이지 않는다. 코드 블록과 제목 없는 일반 체크리스트는 계획으로 계산하지 않는다.

Codex/Claude가 계획을 화면에 제공하지 않는 작업도 있다. 현재 장치의 Codex 0.162.1 Default 모드 로컬 응답 시험에서는 `update_plan`이 지원되지 않아 계획 도구 화면을 만들지 못했다. 화면 분석만으로 항상 현재 태스크를 알아낼 수 있다고 가정하지 않는다.

## 명시적 태스크 보고

프로젝트 skill [miniterm-progress](../.agents/skills/miniterm-progress/SKILL.md)를 추가했다. [공식 skill 문서](https://learn.chatgpt.com/docs/build-skills)에 따라 `.agents/skills`에 두었으며 이 프로젝트에서 실행하는 Codex가 `$miniterm-progress`를 명시적으로 사용하거나 자동 선택할 수 있다. 다른 프로젝트/사용자 전역에는 설치하지 않았다. skill 선택과 갱신 이행은 실제 사용 검증이 필요하며 모든 에이전트에서 자동 동작하는 기능으로 표시하지 않는다.

에이전트는 새 요청의 계획을 `begin`으로 전달하고 현재 태스크·완료 항목·계획·중단 상태가 바뀔 때만 `update`한다. 화면이 스크롤되거나 다시 그려져도 직접 보고는 유지된다. Python 표준 라이브러리 어댑터는 상속된 `MINITERM_NOTIFY_EXE`와 `MINITERM_SESSION_ID`를 사용하고 앱과 helper 모두 `progress-v1`을 지원하는지 확인한다. 이전 helper의 알 수 없는 명령이 창을 활성화하지 않도록 먼저 기존 `sessions` 명령으로 확인한다. 앱에는 Python/API 의존성을 추가하지 않았다.

```text
miniterm.exe progress begin                            # UTF-8 JSON을 stdin으로 전달
miniterm.exe progress update <work-id> <next-revision>   # 전체 현재 계획
miniterm.exe progress read                             # 이 터미널의 보고만 조회
miniterm.exe progress clear <work-id> <next-revision>
```

본문은 `{title,state,tasks:[{text,state}]}`다. 작업 상태는 `running/completed/paused/failed`, 항목 상태는 `pending/running/completed/stopped`다. 앱이 발급한 작업 ID와 정확히 다음 revision을 사용한다. 늦거나 중복된 갱신, 이전 작업·종료된 셸의 보고는 거부한다. `begin`은 새 작업 ID를 발급한다.

Enter 또는 Ctrl+C를 실제 PTY 입력 큐에 보냈을 때 기존 보고를 만료시킨다. 승인 선택의 Enter도 만료되므로 이어지는 에이전트는 현재 계획을 새 `begin`으로 보고해야 한다. 입력을 감지하지 못한 외부 CLI 전환이나 보고를 못 남긴 중단까지 자동 추적하지는 않는다. 호버에는 보고 출처와 마지막 보고 경과 시간을 표시한다. 보고는 에이전트가 주장한 계획 상태이며 실제 명령 성공의 독립적인 판정이 아니다. 응답 완료 알림과 계획 완료는 분리했다.

Codex의 [App Server 계획 이벤트](https://learn.chatgpt.com/docs/app-server)는 별도 프런트엔드 연결이 필요하고 [PostToolUse 훅](https://learn.chatgpt.com/docs/hooks)은 설치·신뢰 설정과 해당 도구 지원이 필요하다. 이번에는 기존 CLI/TUI를 유지하는 skill/로컬 IPC 방식을 구현하고 사용자 전역 에이전트 설정에 훅을 설치하지 않았다.

설정의 창 탭에서 `실행 상태 · 계획 진행률`, `계획 작업 목록`, `AI Battery (하단)`, `프로그램 제목 (상단 표시줄)`, `최근 활동`을 켜고 끌 수 있다. 기본 높이에서는 비율·상태·현재 작업·최근 완료 작업·배터리를 배치한다. 작은 높이에서는 일부 줄을 생략하며 호버로 계획 목록을 확인한다. 요약은 한 번 클릭하면 포커스만 이동하며 더블 클릭 또는 키보드 입력으로 기존 터미널을 펼친다. 확장된 본문도 위치에 관계없이 더블 클릭으로 축소하고 Shift + 더블 클릭은 단어 선택에 사용한다. 이전 `bodyDoubleClickExpands=false` 값은 이 고정 동작을 제한하지 않는다. 요약 때문에 실행 중인 TUI를 작은 VT 크기로 바꾸지 않는다.

화면 분석은 세션별로 캐시하고 VT revision이 바뀔 때만 계산한다. 범위는 최근 history 128행과 현재 화면, 행당 512칸·계획 64개·항목별 256자다. 직접 보고도 세션 메모리에서만 유지하며 최대 48KiB, 작업명 128자·항목별 256자를 허용한다. helper가 짧은 작업 레이블만 현재 사용자용 로컬 IPC로 보낸다. 일반 `sessions` 조회에는 작업 텍스트를 포함하지 않는다. 앱은 보고를 디스크에 저장하지 않고 추가 사용량 API/모델 호출, transcript 읽기, 주기적 프로세스/파일 조회도 하지 않는다.

검증은 `scripts/test.ps1`의 VT/계획/세션별 보고 테스트와 `scripts/verify-ux.ps1 -ProgressSample`의 별도 GUI·helper·skill 어댑터 고정 시험을 사용한다. 실제 CLI/설치된 AI Battery 캡처를 재생하는 opt-in 시험도 제공한다. 실제 모델의 skill 선택·계획 갱신, 물리적인 입력/호버/IME, 원래 goal 메뉴 잔상은 이 고정 시험의 범위 밖이다.
