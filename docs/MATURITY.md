기존 검증 결과는 IMPLEMENTATION.md에 있다. 원시 결과는 artifacts/에 보관하며 테스트용 프로세스와 사용자 실행 프로세스를 구분한다. 테스트를 위해 사용자 에이전트 설정·인증을 자동 변경하지 않는다.

추가 구현: 한 줄 Bash 프롬프트의 항목·별칭·경로 형식·기호 GUI 설정, 다음 프롬프트에서의 적용/복원, 전체 투명도와 취소 복원. 사용자 반경 설정과 binary region은 고정 DWM 모서리로 교체했다. `scripts/verify-appearance.ps1`은 현재 별도 이름을 쓰는 진단 창에서 불투명/투명 화면·테마·창 동작을 검사한다. 이전 스크립트의 프롬프트 GUI 편집·유휴 측정 통과 기록을 새 스크립트의 검증 범위로 간주하지 않는다.

2026-10-11 앞선 점검: 로직 28개, 별도 이름을 사용하는 실제 IPC 1개, Windows AI Battery launcher의 네이티브 TTY/인자/종료 코드/실제 Codex 버전 확인은 통과했다. 실제 AI Battery HUD와 Codex 대화·팝업 클릭은 남아 있다. 당시 Git Bash 통합 시험은 6개 통과·2개 실패였으며 입력 누락이 해결되기 전 P0 완료나 새 설치본 검증 완료로 표시하지 않는다. 사용 중인 설치본과 에이전트 세션은 유지했다.

후속 스크린샷 회귀 수정: 선택/반전 배경이 한글 spacer를 덮는 그리기 순서를 고쳤고 Segoe UI Symbol 폴백으로 AI Battery `❚`를 제공했다. 불투명 다크·라이트 고정 샘플에서 온전한 한글과 막대를 확인했다. 동기화 프레임 종료 누락·읽기 경계·EOF 회복 시험 3개를 추가해 로직 32개가 통과한다. 실제 IPC·Windows bridge도 재검증했다. 최신 Git Bash 통합은 **5개 통과·3개 실패**로, managed prompt의 간헐 입력 누락도 이번 실행에서 재현되었다. 첫 글자 누락은 해결되지 않았다.

사용자가 수정본에서 보고한 실제 Codex 선택 메뉴가 본문 위에 남는 현상은 아직 완료로 표시하지 않는다. 실행 중인 콘솔의 크기는 부모 80×52, Codex 80×51로 배터리 한 줄을 제외한 크기가 맞았다. 동기화 시간 제한 결함을 보완했지만, 이 결함이 해당 스크린샷의 직접 원인인지와 실제 메뉴의 복구는 추가 검증이 필요하다. 라이트 테마에서 명시적인 ANSI 검정/흰색 배경 조합의 대비도 추가 조정이 필요하다. 현재 사용 중인 두 창과 Codex는 재시작하지 않는다.

고정 OS 글꼴 공유 후 1세션 release 앱의 유휴 최대 working set은 184,528,896bytes (175.98MiB)로 200MB 목표를 통과했다. CPU는 30초 동안 측정 해상도 이하였으며 GPU·셸·4세션 부하·입력→pixel 시험을 대체하지 않는다. 이전 helper가 진단 namespace를 무시하는 것도 읽기 전용으로 확인했으므로, 기존 notify 설정을 사용하는 별도 수정본의 알림 라우팅 보완이 필요하다. 사용자 연동 설정과 Windows 등록은 유지했다.

후속 실제 CLI 검증: `scripts/verify-codex-ui.ps1`과 `-Battery`가 별도 CODEX_HOME·고정 로컬 HTTP 오류 제공자에서 Codex 0.162.1의 한글 세션·모델/재개 메뉴를 생성하고 크기를 바꾼다. 출력 재생에서 기준 @xterm/headless와 MiniTerm의 텍스트·ANSI 스타일·커서가 일치했고 메뉴 닫기·배터리 마지막 행 유지도 통과했다. AI Battery compositor는 실제 설치본이며 사용량 데이터만 로컬 고정값이다. 실제 모델 응답 중 goal 선택 화면의 잔상, GPU 픽셀/IME·실제 사용량·알림은 여전히 별도 검증 대상이다. 표시 수정본 PID 29644를 추가 실행했고 기존 두 사용자 창과 세션은 유지했다.

후속 알림 연결 보완: 새 Windows Codex 세션에서 정확히 일치하는 기존 MiniTerm 연결의 helper만 실행별 설정으로 현재 앱에 전달한다. 프로필의 notify 정책·상속, 명시적인 비활성화, 기존 콜백·별칭·함수를 보존한다. `test.ps1 -CodexNotify`의 실제 CLI·로컬 SSE·helper·IPC/Broker 시험이 통과했다. 원시 결과는 `artifacts/codex-notify-75785672-75cc-4b0f-b5ec-28266eabf5cc`다. 현재 사용자 설정에 대해서도 알림을 발송하지 않고 새 helper 선택만 확인했다. Windows toast 클릭, Linux 연결·실제 계정 응답은 여전히 남아 있다. 기존 세 창은 앞선 빌드로 유지하므로 이번 코드가 실행 중인 세션에 적용됐다고 표시하지 않는다.

최신 로직 35개·Clippy·release 빌드와 별도 GUI 회귀 시험이 통과했다. 최신 앱 10초 유휴 최대 working set은 183,828,480bytes (175.31MiB)이며 측정 범위 내 CPU 증가가 없었다. 앱 하나의 값이고 GPU·셸·여러 세션·입력→pixel을 대체하지 않는다. 실제 가상키/스캔 코드를 사용한 별도 ConPTY 시험에서도 resize 후 첫 글자 누락이 재현되어 키 매핑 변경으로 해결되었다고 표시하지 않는다.

최신 추가 보완: ANSI white 배경·검정 글자·기본 반전의 대비를 수정하고 RGB/OSC 지정 색상을 보존했다. 로직은 38개가 통과한다. 실제 정지된 목표의 `Resume paused goal?` 메뉴를 자체 한글 기록에서 재개해 resize·닫기·후속 입력을 직접/AI Battery 구성에서 비교했으며 기준 VT와 일치했다. 실제 도구 실행 중 원래 잔상은 여전히 재현·해결이 필요하다.

같은 최신 빌드에서 4세션 앱의 30초 유휴 최대 working set은 177.43MiB로 해당 샘플이 목표를 통과했고, 테스트 Bash 네 개의 종료도 확인했다. 하지만 확장된 1세션 기호/색 샘플은 197.20MiB로 200,000,000bytes 목표를 초과했다. 메모리 목표를 전체 통과로 표시하지 않으며 원인·출력 부하·GPU·입력→pixel 측정이 남는다. Windows 콘솔 API 단독 1,000회 입력은 누락되지 않았고 MSYS `sysread`는 첫 글자 누락을 재현해 [입력 조사 기록](RESIZE_INPUT_INVESTIGATION.md)에 범위를 정리했다. 입력 오류는 미해결이다. 세 사용자 창은 유지했고 최신 staging 코드를 자동 적용하지 않았다.

최신 요약은 Bash 줄 제거, 상단 제목, 상태·계획 항목·실제 하단 AI Battery, 직접 보고와 작은 창의 줄 수를 제공한다. 비율은 명시된 전체 항목의 완료 표시를 계산하며 응답 종료로 계획 완료를 만들지 않는다. 내부 명령문 대신 읽기 쉬운 활동명을 사용하고 상태·경과 시간도 한글로 표시한다. 기본 생략 툴팁과 별도 안내의 중복을 제거했으며 로직 53개·fmt·Clippy·release가 통과했다. 요약 단일 클릭은 포커스만 이동하며 본문 전반의 더블 클릭으로 확장·축소한다. 기존 false 설정에서도 위·가운데·아래 위치를 검사했다.

목표 재개창의 중앙 표시는 실제 기본 Codex/AI Battery 전체 화면 경로에서 재현했다. 이전 강제 `--no-alt-screen` 캡처는 그 경로를 검증하지 못했다. MiniTerm Windows 실행 연결이 inline 모드를 사용하도록 바꾸고 실제 GUI의 하단 위치·배터리 유지·선택 후 닫기·다크/라이트를 확인했다. 자체 목표·로컬 제공자·고정 사용량 시험이며 실제 계정/모델과 진행 중 도구 출력은 추가 확인이 필요하다. 사용자 별칭·함수와 이미 실행 중인 앱은 유지한다.

175.02MiB 기본 요약 샘플은 당시 샘플만 통과했고, 이후 직접 보고 샘플은 205,062,144bytes로 실패했다. 현재 UI 수정에서 메모리 검사를 다시 수행하지 않았으며 목표는 통과하지 않았다. 첫 글자 누락·실제 IME/알림/부하 검증도 남아 있다. [진행 체크리스트](WORK_CHECKLIST.md)와 [요약 동작](MINI_SUMMARY.md)을 확인한다.

입력 조사 추가: 테스트 소유 Bash/Perl의 실제 DLL import 호출을 기록해, 자식이 크기 이벤트를 조회한 사이 부모가 그 이벤트를 제거하고 키를 되돌리며, 자식의 이전 개수에 따른 discard가 `p`를 버리는 순서를 관찰했다. 고정 요청 21의 실제 결과도 `rintf`였다. 이후 자체 SDK에서 기준 DLL과 후보를 컴파일했고 v3는 이벤트 소비 순서와 마지막 알림 크기의 분리로 raw/canonical 각각 1,000회, SIGWINCH/siglongjmp 1,000회, 기존 연동 10개를 통과했다. 같은 후보 DLL의 별도 native GUI도 요약·툴팁·진행 보고·더블 클릭을 통과했다. [검증 범위·원시 기록](patches/MSYS_RUNTIME_VALIDATION.md)을 확인한다. master 비활성화 대조 실험은 실패했으며 제품 적용·전체 잡 제어/실기·다른 버전/부하는 남는다. 후보는 사용자 Git이나 제품 기본 프로필에 적용하지 않았다.

상단/요약 후속: 세 아이콘과 넓어진 제목 영역, 완료 항목 비율·현재 태스크 우선 표시, 프로젝트 `miniterm-progress` skill과 세션별 직접 보고를 구현했다. 로직 50개·Clippy·release, 고정 GUI의 한글 보고·33→66% 갱신·중단·완료·초기화·오래된 보고/거짓 완료 거부와 구버전 어댑터 차단이 통과했다. 모델이 skill을 선택하고 지속적으로 보고하는지, 물리적 Enter/Ctrl+C와 승인 후 재보고는 미검증이다. 보고를 모든 CLI의 자동 진행도 수집으로 간주하지 않는다. 이번 10초 유휴 앱 working set은 205,062,144bytes로 목표를 다시 초과했다. 최신 기록은 `artifacts/ux-d3f76684-664e-4936-9620-c5843ddc223b`와 [체크리스트](WORK_CHECKLIST.md)에 유지하며 기존 P0 항목은 남는다.
